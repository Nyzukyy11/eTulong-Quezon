# Acceptance scenarios and traceability

Actual methods are in Tests/AcceptanceTests.cs. All exercise the real ASP.NET Core HTTP pipeline and real PostgreSQL, except explicitly scoped client-transport/picker doubles. Each scenario has an independent migrated database and fixed clock2030-01-15. See evidence/final.trx for actual outcomes.

| ID / actual method suffix | Preconditions and action | Expected business/persisted outcome | Verification |
|---|---|---|---|
| FP01_IntakeDocumentsSubmissionAndRetry | Empty operational database; create invalid/valid drafts, submit without images, reject invalid image, attach required files, invoke real ViewModel attachment/cancellation with controlled picker, submit and retry | Invalid attempts unchanged; draft consumes none; complete submission has one reservation and one capacity increment; retry/duplicate applicant cannot consume another | xUnit: HTTP statuses/Location/DTOs, ViewModel feedback, fresh counts and unchanged snapshots |
| FP02_TwoApplicantsCompeteForLastSlot | Two complete drafts; capacity1; hold batch row lock; start two independent HTTP clients; observe both database requests waiting; release gate | Exactly one HTTP200 and one409; one Submitted case, one Draft case, one reservation, reservedCount1; duplicate reservation rejected by real database | xUnit: actual pg_stat_activity lock observation, two clients/contexts, fresh PostgreSQL read, unique SQLSTATE23505 |
| FP03_ReviewReplacementAndEndorsementRules | Submitted case; try endorsement before acceptance; request replacement; attach new copy; review all documents; endorse; try wrong role / late replacement | Missing acceptance blocks endorsement; replacement clears review; accepted copies allow Endorsed; staff cannot decide as official; frozen endorsed documents unchanged | xUnit: role/status/remarks, fresh unchanged snapshots and accepted reviewer associations |
| FP04_OfficialDecisionAndDenialFreeCapacity | Endorsed case in one-slot batch; deny with required remarks; try forbidden operations; submit another applicant and approve | Denial records official and returns slot exactly once; next applicant can submit; approval changes reservation to Awarded without second capacity increment | xUnit: HTTP transitions, official identity, fresh batch and decision rows |

WF1 coverage: FP01/FP02/FP06/FP08. WF2 coverage: FP03/FP04/FP05. Relationship: FP03–FP07 operate on WF1's actual case/reservation/documents. Advanced optionA: FP02/FP04/FP05/FP06.
